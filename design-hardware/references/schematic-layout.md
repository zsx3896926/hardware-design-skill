# 原理图排版与看图验收

目标是让另一位工程师能顺着图理解、检查和调试电路；新手无需先学排版术语。创建原理图、增加功能块或整理乱图时执行本文件。既有项目风格优先；仅检查任务保持只读。这里约束图面表达，不替代电气设计，也不声称修改了执行器的自动布局算法。

需要程序化重排已有工程（读真实几何、功能分区、区内求解、合页、受保护写入、前后复核）时，先读 [原理图排版引擎](schematic-layout-engine.md)；本文件继续作为图面表达与验收规则，两者不互相替代。

## 1. 先保全连接，再安排图面

- 实际读入目标工程、页、器件身份/位号、符号单元、物理脚号、pin-net、NC、端口作用域与SCH-PCB绑定。保存工具支持的恢复依据。
- 对整理任务建立整理前的连接基线：每个稳定器件ID的物理脚号对应网络成员集合、NC集合、完整型号/封装与绑定。网络内部ID可能因重建导线改变，比较成员关系和作用域，不能只比较ID或网名。
- 默认只改位置、方向、导线路径、标记位置和显示属性。保持器件、数值、脚号、有效电平、网络、NC与装配变体不变。分页或改端口类型会影响作用域，须作为连接变更单独验证。
- 截图只用于发现视觉问题。无法从截图判定的交叉、短接、端口连接与遗漏，先读工程；不凭像素增加连接点、改名、删线或补NC。只有截图时交付整理建议，不宣称真实工程已整理。

## 2. 先设计模块，再组合页面

1. 按电气功能划块，例如输入保护/稳压、主控及最小系统、采集、通信、功率输出、外部接口。每块保留完整可理解的局部电路，不把每颗电阻单独成块。
2. 根据真实引脚几何安排模块内部：核心器件、外围、端口和注释一起设计；先确定外围拓扑，再计算占用范围。不要先摆一张器件矩阵，再让自动连线跨全页寻找脚。
3. 为块间主信号确定阅读顺序，通常左到右、上到下；电源路径通常输入到转换再到负载。大芯片允许外围按实际引脚分布就近放置，不能为了方向口号反复绕线。

**先读真实几何，不用固定坐标模板。** 从当前工程回读页面可用范围（`Width/Height`）、每个器件符号本体边界、每个物理引脚的实际 `x/y` 和方向，再决定放置和导线端点。不同图幅、符号、旋转和库变体都不同；把 `(3000,3000)` 或某个开源项目的坐标当通用模板会直接越出图框。2026-10-21 的真机案例中，器件先放在 `(3000,3000)`，导出图显示整条电路远在 A4 图框外；读取页面 `1170×825` 后移到 `(300,400)` 并保留器件身份，图面才恢复正常。页面单位也不是毫米/英寸，不能自行换算成固定值。
4. 量取每块完整可见边界，包括符号、引脚文字、位号、数值、型号、端口、网络标签、NC和注释。预留接线通道、块间留白、标题和图签区域；不能只用器件中心或符号外框估算。
5. 依据内容选择页面和分页。单页紧凑时按阅读顺序排列，同一行顶齐，下一行按本行最高块推进；块宽高各自适配内容。框线可沿项目风格使用，但不强迫所有块同尺寸，不在模块外再套多重装饰框。
6. 内容放不下时优先移块、分行、选合适图幅或合理分页；不无限缩小文字、压缩间距、裁掉引脚或把关键参数藏起来。分页需保留功能完整性与端口追踪；不要为美观擅自删源页。

## 3. 局部用短线，跨区用明确的网名

| 场景 | 表达方式 | 避免 |
|---|---|---|
| 分压、反馈、滤波、保护、晶振、启动/复位外围 | 保留容易跟读的短线和局部支路，器件靠近所属电路 | 用标签拆散每个节点，看不出拓扑 |
| 主控到远端接口、跨功能块/跨页 | 两端短引线加有语义的标签/端口，核对名称与作用域 | 长线绕芯片、穿过别的模块 |
| 常用电源和地 | 适当位置重复使用经验证的电源/地符号；局部共享短母线可保留 | 绕整页的3V3/GND大框或将不同地同名合并 |
| 同组并行信号 | 相邻、同向、相同排列逻辑；只有工具支持且语义可验证才用总线 | 为了齐整交换真实引脚或把总线图形当电气连接 |
| 差分、隔离、模拟敏感链路 | 成对呈现极性与域边界，局部拓扑清楚，必要约束有注释 | 仅凭原理图对称就声称PCB阻抗/隔离已满足 |

去耦按所属电源域和供电脚组表达，可以放在器件附近或独立、明确关联的去耦组；不要用巨大矩形电源/地回路把电容包到页面边上。原理图的视觉距离不证明PCB上的去耦距离。

物理脚号顺序不等于原理图阅读顺序。优先使用可信库中已核对的功能分组符号/单元；不能为了好看直接改库脚号、交换引脚或临时重画芯片。既有符号难以直连时用短引线与明确标签化解，不牺牲pin-pad映射。

### 3.1 正反例：短线、标签与拓扑

| 场景 | 正例 | 反例 | 为什么 |
|---|---|---|---|
| 分压/反馈/滤波/晶振/复位外围 | 保留局部短线和支路，器件靠近所属节点 | 每个节点都挂标签，拓扑被拆成“网名列表” | 读者要能直接跟出分压比、反馈极性和环路 |
| 主控到远端接口/跨功能块 | 两端短引线 + 有语义的标签/端口，名称成对 | 长线绕芯片、穿别的模块，或只在一端有标签 | 跨块表达要能按名称追踪，又不制造大环线 |
| 电源/地 | 在真实供电脚附近重复使用经验证的电源/地符号 | 用绕整页的大矩形把 3V3/GND 全包起来 | 图形母线不证明低阻抗/回流；还会压住内容 |
| 同组并行信号 | 相邻、同向、同排列，必要时用工具支持且语义可验证的总线 | 为了齐整交换真实引脚，或画总线图形但没有网表语义 | 可读性不能改变pin-pad或真实连接 |
| 差分/隔离/模拟敏感链路 | 成对呈现极性、域边界和必要约束注释 | 只凭左右对称就声称PCB阻抗/隔离满足；把差分拆到不同页且无说明 | 原理图表达意图，PCB/手册证据才证明实现 |
| 交叉/连接点 | 错开含糊的四向交点；连接点对应真实拓扑 | 用装饰圆点假装连接；导线交叉处靠“看起来像”判断 | 交叉不连接与连接必须能从图和回读区分 |

标签必须落在真实连接端上；同名网络要核对作用域（页内/工程/端口方向），不能把“同名”当成“已连通”。网络端口用于跨模块/跨页时，方向、名称和域要成对；不要把电源地也塞进每个信号端口。总线、差分和反馈链路的表达边界见 [原理图细节](schematic-details.md) 与 [连接表契约](connectivity.md)。

### 3.2 模块内部几何：按引脚，不按外框

- 先回读核心器件的物理引脚位置/方向/间距，再放外围；外围的朝向由它要连的引脚决定，不是先摆成矩阵。
- 多单元器件（如运放/门电路）按单元分别核对 `SubPartName`、电源脚和未用单元处理；隐藏电源脚不能凭“图上没画”当成不存在。
- 符号变体/镜像/旋转后，实际引脚端点和文字位置会变；写入后回读 `x/y/rotation/mirror` 与引脚坐标，不能沿用旋转前的坐标。
- 局部连接优先直接画线；只有跨区、跨页或长距离才用标签。为减少一条线而增加一串标签，通常让拓扑更难读。
- 模块边界按“符号+引脚文字+位号+数值+端口+注释”的完整可见范围计算，不只按器件中心或外框。留出接线通道、块间留白和图签区域。
- 逻辑布局与PCB物理邻近分开：原理图上把去耦画在芯片旁边，不证明PCB上去耦就在引脚旁；PCB阶段仍需按实际回路放件。

## 4. 导线、标记与文字的几何纪律

- 使用项目网格，以实测引脚端点为锚点；主连线优先水平/垂直，用合理转折。减少不必要的交叉、折返、长距离平行和短线碎片，但不能用“最短线长”单一目标压倒可读性。
- 导线不得穿过无关符号本体、引脚文字、位号、型号、注释或图签；不沿元件边缘挤线。跨线不连接时保持清楚，优先错开含糊的四向交点；连接点必须对应实际拓扑，不用装饰圆点假装连接。
- 标签放在真实连接端上并朝向清楚，默认沿易读方向排列，给相邻端口错开位置和合理短引线；不堆叠、不落在拐角、不与脚名争同一空间。旋转后回读实际电气落点，尤其注意EasyEDA标记旋转/存储差异。
- 沿用现有字号层级、单位、命名与颜色。位号/数值清楚，必要的耐压、功率、精度、完整型号可读；长型号可换位置或独立注释并关联器件。采购C号等属性可按项目风格显示，但BOM字段必须保留。不要把全部属性直接堆在符号旁。
- 标题、框线、端口和元件一起计算碰撞；标题放在留出的空档，框线在内容之外保留内边距。不要假定“框已画好”等于模块已整理。
- 外部接口注明电压、极性、信号含义及必要的板端视角。TX/RX的命名沿项目约定并注明观察端；不得为了阅读顺序反接收发。
- 同类电路保持一致的朝向、元件排列和标注方式。电源通常朝上、地通常朝下属于默认阅读习惯；负电源、隔离、反馈和既有符号允许合理例外。

间距、字号、线宽与图幅从项目设置、实际文本包围盒和执行器单位推导；不要把某个开源项目的像素、英寸或网格数设为全行业常数。没有文本测量能力时按真实导图检查并保守留白，不声称已做精确碰撞检测。

## 5. Agent执行与闭环验收

按“连接基线 → 模块局部几何 → 页面组合 → 小批写入 → 实际回读 → 导图看图 → 修正”的顺序推进，遵循当前执行器协议。在easyeda-agent提供compose/apply时，把排版决定写回其源数据/规划，再执行并回读；不要在画布上临时整理后让下一次apply覆盖。

将问题分级处理：先解决连接/身份变化、导线穿件、文字遮脚、越界和交点歧义；再处理跨区长线、外围散落、标题冲突；最后统一对齐与留白。不要为了减少一处留白重排整个正确页面。

每次生成或实质整理后完成两种互不替代的验收：

**连接与工程验收**：将实际回读与计划、整理前基线比较，核对物理脚网络成员、NC、域/端口作用域、位号/库身份及SCH-PCB绑定。运行当前工具可用的布局、连接、跨页与官方DRC检查，逐项记录错误/警告/未覆盖范围。几何整理出现连接差异时停止继续美化，先恢复或查清差异；不把改变网络当作排版成功。

**实际图面验收**：通过EDA官方导出得到当前页图；查看整页，再以可读文字的局部尺度逐块检查。不能只检查缩略图或计划坐标。逐项回答：
- 整页是否看得出功能分区与阅读顺序？有无孤立器件、失衡的大空洞或拥挤角落？
- 每块的局部拓扑能否直接跟读？外围归属是否明确？跨块是否有可避免的大环线？
- 所有位号、必要数值、脚名、端口、标题是否可读，是否重叠、压线或越框？
- 交叉与连接点是否清楚，标签是否真落在端点，跨页能否按网名/页名追踪？
- 新增/改动部分与保留部分衔接是否一致？分区框有没有切线、压标题或漏包内容？

已有实际回读的符号本体与文字边界时，可按 [离线工具契约](offline-tools.md) 运行sch_layout_check辅助定位碰撞/穿越；文本只有锚点或计数不全时保持覆盖不足。脚本不判电气、去耦距离或阅读质量，不能据候选自动改网/删对象，也不替代本节实际导图验收。

图面几何输入还可带 `title_block`、`module_frames`（含 `contains` 成员）、`attachment_points`（真实引脚/标记/端口点）、`label_anchors`（网名标签锚点）与 `policy.connection_tolerance`。对应候选包括：器件/文字压图签、导线穿图签、模块框越页/互相重叠/切器件、成员缺失、导线端点悬空、同一连接点出现多个网络、标签悬空或标签网名与所在导线不符。它们仍只是候选：`attachment_points` 不完整会把正常端点报成悬空，`contains` 只是声明，标签在线上也不证明全页网络正确。`electrical_verified/visual_verified` 始终为false，修复后仍要回读网表并实际导图。

官方CLI可用时，按 [EDA执行](eda-execution.md) 把排版决定落成受控动作并做真实验收：

```bash
python scripts/eda_exec.py read --project <副本> --schematic Demo --page-name P1 --output before.json
python scripts/eda_exec.py apply --project <副本> --plan tidy.json --dry-run
python scripts/eda_exec.py apply --project <副本> --plan tidy.json --save
python scripts/eda_exec.py export --session <id> --schematic Demo --page-name P1 --kind png --output after.png --width 1600
python scripts/eda_exec.py export --session <id> --schematic Demo --page-name P1 --kind netlist --output after.net
python scripts/eda_exec.py reopen-check --project <副本> --snapshot after.json --schematic Demo --page-name P1
```

先 `--dry-run` 看冲突，再小批写入；保存只在逐项回读通过后发生；重开比较稳定身份/连接。半离线会话的结论不能写成全在线；没有实际导图/看图时不能宣称“图面已整理完成”。

发现问题就修改源布局、重新写入受影响部分，并复查其连接及实际导图。检查器未报错但肉眼仍混乱时不能交付“已整理完成”。工具缺导图/视觉检查能力时列明未完成该项，继续可做的检查，不用DRC、分数、坐标检查或用户“帮忙看一下”冒充看图验收。反复无改善时定位执行器/布局能力限制，留下具体问题位置与接续方案，不无限重试。

最终显式保存。对用户简明报告整理范围、真实检查结果、剩余问题与工程位置；有真实前后图时可给对照。没有实际打开和修改EDA时，只能说规则/规划已更新。新手无需批准技术正确性。

## 6. 学习样本与适用边界

以下为2026-10-20实际查看的原作者图纸，借鉴表达方法，未把其电路值、版图参数或整页图纸复制进Skill；这些观察是本Skill的归纳，不是原作者颁布的强制规范。

- [SparkFun ESP32 Thing Plus：单页原理图](https://cdn.sparkfun.com/assets/6/d/c/6/c/ESP32_Thing_Plus_Schematic.pdf)，第1页：供电、USB串口、启动控制等按功能分开；以网名连接远端模块，保留局部支路。适用于学习如何避免把主控连成一团。其[原作者硬件仓库](https://github.com/sparkfun/ESP32_Thing_Plus)另有许可，复用硬件须单独遵守。
- [SparkFun Thing Plus ESP32-S3](https://cdn.sparkfun.com/assets/5/e/6/5/0/SparkFun_Thing_Plus_ESP32-S3.pdf)，第1–2页：主控/供电与外围分页，保留局部连线和接口网名，说明性文字关联相应模块。可学习分页与注释组织；不要照抄其某一叠层的走线参数。
- [Arduino UNO R3官方原理图](https://docs.arduino.cc/resources/schematics/A000066-schematics.pdf)，第1页：主控、USB串口、稳压与接插件按区域表达；局部电路可跟读，远端用重复网名关联。借鉴区域组织，不把历史图纸的密度与所有细节视为最佳模板。

检索立创开源硬件参考时同样要求打开实际原理图，核对作者、版本、原始文件与许可，再抽取适合当前项目的表达方式。不要仅凭封面、点赞、成品照或“开源”标签认定电路与图面都优秀；无需因追求排版而换掉已经验证的电气方案。

8类典型任务的离线几何基准、预期候选与检查方法见 [原理图排版基准集](schematic-benchmarks.md)；运行 `python scripts/schematic_benchmark.py` 可复现候选。基准是故意有缺陷的离线快照，不是8张已真机绘制的图。真实执行通道的读写/保存/重开/导图证据见 [EDA执行证据](../../docs/evidence/eda-2026-10-21/README.md)，它只证明该演示页的闭环，不能扩展成所有排版案例都已真机验证。
